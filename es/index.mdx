title: "Visión General de Raigal"
description: "Control de calidad de código y detección de patrones de IA para equipos de ingeniería."
---

Raigal detecta patrones defectuosos introducidos por asistentes de programación asistidos por IA, como comentarios triviales, excepciones silenciadas (`swallowed-exception`), aserciones de tipo inseguras (`as any`) y llamadas dinámicas de riesgo (`eval`). Reúne formateo, linting, análisis de complejidad, reglas de seguridad y detección de patrones en un único comando que devuelve una puntuación de 0 a 100.

Junto con [Raigal Cloud](https://app.raigal.dev) y la [GitHub App oficial de Raigal](https://github.com/apps/raigal-cloud), evalúa pull requests, gestiona comprobaciones de estado para la protección de ramas, organiza las incidencias en un tablero de remediación en 4 etapas y ejecuta reparaciones con agentes de programación.

<Info>
  Los archivos de código fuente completos nunca se suben ni se almacenan en Raigal Cloud. El análisis de AST, la ejecución de linters y el cálculo de complejidad ocurren localmente en su máquina o runner de CI. Durante la evaluación de pull requests en CI, se envía una vista previa del parche (limitada a 20 KB) con enmascaramiento de credenciales (`maskSecrets`) para inspeccionar cambios en el tablero.
</Info>

## Qué detecta Raigal

Los asistentes de programación como Claude Code, Cursor, Copilot u OpenCode aceleran el desarrollo, pero suelen introducir defectos concretos:

* Comentarios triviales que solo repiten el nombre de funciones o variables.
* Aserciones de tipo que eluden el compilador (`as any`).
* Bloques `catch` vacíos o excepciones silenciadas sin registrar.
* Consultas SQL concatenadas, inyección de comandos o llamadas a `eval()`.
* Bloques de código duplicados y funciones con complejidad ciclomática excesiva.

Raigal evalúa el código en local mediante hooks de agente, en CI con cada commit y en pull requests antes de la fusión.

## Primeros pasos

<Steps>
  <Step title="1. Crear cuenta en Raigal Cloud">

Cree el espacio de trabajo de su organización en [app.raigal.dev](https://app.raigal.dev) con una prueba de evaluación de 14 días e invite a su equipo. [Guía de Configuración de la Organización](/es/primer-contacto/configuracion-cliente)

  </Step>

  <Step title="2. Instalar la GitHub App de Raigal">

Conecte sus repositorios con la [GitHub App oficial de Raigal](https://github.com/apps/raigal-cloud) para habilitar comprobaciones automáticas en pull requests. [Puerta de Calidad en Pull Requests](/es/automatizacion-y-ci-cd/pull-requests)

  </Step>

  <Step title="3. Configurar el flujo de CI">

Añada un flujo de GitHub Actions para evaluar los pull requests y enviar las puntuaciones al tablero. [Pipelines de CI/CD y GitHub Actions](/es/automatizacion-y-ci-cd/ci-cd)

  </Step>

  <Step title="4. Configurar herramientas locales y hooks">

Instale el CLI (`raigal scan`, `raigal fix`) y active los hooks de intercepción para Claude Code o Cursor. [Guía de Inicio Rápido](/es/primer-contacto/inicio-rapido)

  </Step>
</Steps>
