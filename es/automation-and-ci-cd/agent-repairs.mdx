---
title: "Reparación automática con agentes"
description: "Sesiones de reparación en git worktrees aislados con asistentes de código locales."
---

Para corregir problemas que requieren refactorización o cambios semánticos, `raigal agent` abre una sesión de trabajo con una herramienta local de IA dentro de un git worktree aislado.

## Cómo funcionan las reparaciones en worktrees

Para proteger tu rama activa de modificaciones no deseadas, `raigal agent` aísla todos los cambios:

1. Raigal crea un worktree temporal en `.raigal/worktrees/agent-<timestamp>-<pid>/`, registrado en `.git/info/exclude` para no alterar el estado de git.
2. El proveedor del agente (Claude Code, OpenCode o Codex) recibe el diagnóstico, el contexto de los archivos y la nota objetivo en su prompt.
3. El agente aplica los cambios y verifica las correcciones dentro del worktree.
4. Tras revisar el diff resultante, puedes ejecutar `raigal agent apply <session-id>` para fusionar los cambios en local o pasar `--pr` para abrir un pull request en GitHub.

## Proveedores compatibles

Raigal se conecta con tres herramientas de programación locales:

| Proveedor | Invocación | Comando de configuración |
|---|---|---|
| Claude Code | `claude` | `raigal agent connect claude` |
| OpenCode | `opencode` | `raigal agent connect opencode` |
| Codex | `codex` | `raigal agent connect codex` |
| Detección automática | Selección automática | `raigal agent use auto` |

Comprueba los proveedores instalados en tu máquina:
```bash
raigal agent providers
```

## Flujos de trabajo

### 1. Sesión interactiva de reparación local

Prueba y valida las modificaciones antes de crear un commit en git:

```bash
# Previsualiza qué abordará la sesión de reparación
raigal agent plan .

# Inicia la sesión interactiva con el agente
raigal agent --provider opencode .

# Consulta las sesiones de reparación activas y recientes
raigal agent sessions .

# Examina los cambios introducidos y diagnósticos de una sesión
raigal agent show <session-id>

# Aplica las modificaciones aprobadas a tu rama de trabajo
raigal agent apply <session-id>
```

### 2. Creación automática de pull requests (`--pr`)

Para generar una rama y abrir un pull request automáticamente:

```bash
raigal agent --provider claude --pr --target 95
```

Con la opción `--pr`, Raigal:
1. Aplica correcciones automáticas seguras y traslada los problemas restantes al agente.
2. Comprueba que las pruebas pasan y la nota alcanza el objetivo fijado en `--target` (por defecto: 90).
3. Confirma los cambios en una rama de reparación (`raigal/repair-...`).
4. Publica la rama en el repositorio remoto y abre un pull request en GitHub.
5. Envía la telemetría a Raigal Cloud para crear una tarjeta en la pestaña **Agent Actions**.

### 3. Sincronización del ciclo de vida (`report-pr-closed`)

Cuando se fusiona o cierra un pull request en GitHub, actualiza el estado del panel con este flujo de GitHub Actions:

```yaml
# .github/workflows/raigal-pr-closed.yml
name: Ciclo de vida de PRs Raigal

on:
  pull_request:
    types: [closed]

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - name: Notificar cierre de PR a Raigal Cloud
        env:
          RAIGAL_TOKEN: ${{ secrets.RAIGAL_TOKEN }}
          RAIGAL_API_URL: ${{ secrets.RAIGAL_API_URL }}
        run: |
          npx -y @methiu/raigal@latest report-pr-closed --pr ${{ github.event.pull_request.number }} ${{ github.event.pull_request.merged && '--merged' || '' }}
```

<Info>
  Al abrir un pull request con `raigal agent --pr`, se crea una tarjeta en la pestaña **Agent Actions**. Cuando se fusiona el PR, `report-pr-closed` la mueve a **Merged** y anota la ganancia de puntuación.
</Info>
