# CI/CD pipelines and automated gates

Configure Raigal to check pull requests in CI, enforce quality gates, and report scores to your dashboard.

Running `raigal init` automatically detects your repository's CI provider and scaffolds your workflow with zero guesswork.

## Environment variables

Provide these variables in your CI environment:

| Variable | Required | Description | Example |
|---|---|---|---|
| `RAIGAL_TOKEN` | Yes* | Organization API key (`rgl_live_...`) | `rgl_live_8f3a9b...` |
| `RAIGAL_ORG_ID` | Optional | Organization ID (`org_...`), required only if repository owner belongs to multiple Raigal organizations | `org_2tQ...` |
| `RAIGAL_API_URL` | Optional | Custom backend URL (defaults to `https://app.raigal.dev`) | `https://app.raigal.dev` |

*Note: In GitHub Actions jobs configured with `permissions: id-token: write`, static tokens are not required because Raigal validates the runner using zero-token GitHub OIDC directly.*

## GitHub Actions

### 1. Hardened pull request check

Create `.github/workflows/raigal.yml` to evaluate pull requests, report to your dashboard, and optionally generate SARIF annotations:

```yaml
name: Raigal Quality Gate

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

permissions:
  contents: read
  id-token: write        # Enables zero-token cryptographic OIDC authentication
  security-events: write # Required for GitHub Code Scanning SARIF upload

jobs:
  gate:
    name: Code Quality & Slop Gate
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # Full git history required for base diff resolution

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Run Raigal Quality Gate
        env:
          RAIGAL_TOKEN: ${{ secrets.RAIGAL_TOKEN }}
          # RAIGAL_ORG_ID: ${{ vars.RAIGAL_ORG_ID }} # Required if owner belongs to multiple orgs
        run: |
          if [ "${{ github.event_name }}" = "pull_request" ]; then
            npx --yes @methiu/raigal@latest ci --changes --base origin/${{ github.base_ref }}
          else
            npx --yes @methiu/raigal@latest ci .
          fi

      - name: Generate SARIF Security Report
        if: always()
        run: npx --yes @methiu/raigal@latest scan . --sarif > raigal-results.sarif

      - name: Upload SARIF to GitHub Code Scanning
        if: always() && github.event.pull_request.head.repo.full_name == github.repository
        uses: github/codeql-action/upload-sarif@v3
        continue-on-error: true
        with:
          sarif_file: raigal-results.sarif
          category: raigal
```

{% hint style="info" %}
Uploading SARIF reports to GitHub Code Scanning on private repositories requires GitHub Advanced Security (GHAS) enabled on your GitHub enterprise account. On public repositories, code scanning is included for free.
{% endhint %}

### 2. Pull request close and merge sync

{% hint style="info" %}
If you use the **Raigal GitHub App**, this step is unnecessary. The app receives `pull_request.closed` webhook events directly from GitHub and updates your board automatically.
{% endhint %}

For standalone CI environments without the GitHub App, sync card status when PRs merge or close:

```yaml
name: Raigal PR Lifecycle

on:
  pull_request:
    types: [closed]

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Synchronize PR with Raigal Cloud
        env:
          RAIGAL_TOKEN: ${{ secrets.RAIGAL_TOKEN }}
        run: |
          npx --yes @methiu/raigal@latest report-pr-closed --pr ${{ github.event.pull_request.number }} ${{ github.event.pull_request.merged && '--merged' || '' }}
```

## GitLab CI

In `.gitlab-ci.yml` (auto-generated by `raigal init`):

```yaml
raigal_quality_gate:
  image: node:24
  stage: test
  script:
    - if [ -n "$CI_MERGE_REQUEST_IID" ]; then npx --yes @methiu/raigal@latest ci --changes --base "$CI_MERGE_REQUEST_DIFF_BASE_SHA"; else npx --yes @methiu/raigal@latest ci .; fi
  variables:
    RAIGAL_TOKEN: $RAIGAL_TOKEN
    # RAIGAL_ORG_ID: $RAIGAL_ORG_ID # Required only if repository owner belongs to multiple Raigal orgs
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```

Configure `RAIGAL_TOKEN` under **Settings > CI/CD > Variables**.

## Bitbucket Pipelines

In `bitbucket-pipelines.yml` (auto-generated by `raigal init`):

```yaml
pipelines:
  default:
    - step:
        name: raigal quality gate
        image: node:24
        script:
          - npx --yes @methiu/raigal@latest ci .
        secrets:
          - RAIGAL_TOKEN
          # - RAIGAL_ORG_ID
  pull-requests:
    "**":
      - step:
          name: raigal quality gate
          image: node:24
          clone:
            depth: full   # branch diffs need full history
          script:
            - git fetch origin "$BITBUCKET_PR_DESTINATION_BRANCH"
            - npx --yes @methiu/raigal@latest ci --changes --base FETCH_HEAD
          secrets:
            - RAIGAL_TOKEN
            # - RAIGAL_ORG_ID
```

Configure `RAIGAL_TOKEN` under **Repository settings > Repository variables**.
